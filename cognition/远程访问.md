# PanWatch 远程访问说明

本文说明两种部署访问方式：

- 在一台电脑上运行 PanWatch，让同一局域网内的手机访问。
- 部署到云服务器，让其他人通过公网链接访问。

PanWatch 后端入口是 `python server.py`，监听地址已配置为 `0.0.0.0:8000`。生产模式下前端静态文件由后端同端口提供；开发模式下前端 Vite 服务监听 `0.0.0.0:5183`，并把 `/api` 代理到本机 `8000`。

## 一、本地电脑部署，手机访问

### 方案 A：Docker/生产模式，推荐

这种方式手机只访问一个地址：`http://电脑局域网IP:8000`。

1. 在电脑上构建镜像：

```bash
docker build -t panwatch:local .
```

也可以使用项目脚本构建：

```bash
./build.sh local
```

2. 启动容器：

```bash
docker run -d \
  --name panwatch \
  --restart unless-stopped \
  -p 8000:8000 \
  -v panwatch_data:/app/data \
  -e TZ=Asia/Shanghai \
  -e AUTH_USERNAME=你的用户名 \
  -e AUTH_PASSWORD=你的强密码 \
  -e JWT_SECRET=替换成一段随机长字符串 \
  panwatch:local
```

3. 找到电脑的局域网 IP：

```bash
# macOS，Wi-Fi 通常是 en0
ipconfig getifaddr en0

# Linux
hostname -I

# Windows
ipconfig
```

4. 手机和电脑连接同一个 Wi-Fi，在手机浏览器打开：

```text
http://电脑局域网IP:8000
```

例如：

```text
http://192.168.1.23:8000
```

5. 如果手机打不开，按顺序检查：

- 电脑和手机是否在同一局域网。
- 容器是否运行：`docker ps`。
- 本机是否能打开：`http://127.0.0.1:8000`。
- macOS/Windows 防火墙是否允许 Python/Docker 监听入站连接。
- 路由器是否开启了 AP 隔离、访客网络隔离；如果开启，同一 Wi-Fi 下设备也可能互相不可访问。

### 方案 B：本地开发模式

适合改代码时调试。手机访问前端开发服务：`http://电脑局域网IP:5183`。

1. 启动后端：

```bash
python server.py
```

2. 启动前端：

```bash
cd frontend
pnpm install
pnpm dev
```

3. 手机打开：

```text
http://电脑局域网IP:5183
```

本项目的 `frontend/vite.config.ts` 已配置：

- `host: 0.0.0.0`
- `port: 5183`
- `/api` 代理到 `http://127.0.0.1:8000`

所以手机访问 `:5183` 时，API 请求会先打到电脑上的 Vite 服务，再由 Vite 转发给电脑本机后端。

### IP 访问出现 HTTP 502

如果 Vite 终端显示类似：

```text
Network: http://30.249.116.2:5183/
```

但浏览器打开后提示 `HTTP ERROR 502`，优先检查代理。当前电脑如果开启了 Clash、Surge、公司代理或系统代理，而代理绕过列表没有包含这个 IP，浏览器可能会把 `30.249.116.2:5183` 发给代理处理，代理无法访问本机开发服务时就会返回 502。

处理方式：

1. 浏览器或代理客户端里把本机 IP 加入绕过/直连列表，例如：

```text
30.249.116.2
30.249.116.0/19
localhost
127.0.0.1
```

2. 终端环境可以临时追加 `NO_PROXY` 后再启动：

```bash
export NO_PROXY="$NO_PROXY,30.249.116.2,30.249.116.0/19"
./start_pan_hot.sh
```

3. 如果是手机访问，需要手机和电脑连接同一个网络，并确认手机上的代理/VPN 也不要代理这个地址。
4. 如果关闭代理后仍无法访问，再检查 macOS/Windows 防火墙是否允许 Node/Python 入站、当前 Wi-Fi 是否是访客网络、路由器是否开启 AP 隔离。

补充说明：`30.x.x.x` 不是常见家庭路由器的 `192.168.x.x`、`10.x.x.x`、`172.16.x.x` 私网地址，但公司或特殊网络可能会这样分配。只要手机和电脑在同一二层网络且代理不拦截，仍然可以访问。

### 局域网访问安全建议

- 不要使用默认或弱密码，建议设置 `AUTH_USERNAME`、`AUTH_PASSWORD`、`JWT_SECRET`。
- 局域网内访问一般不需要 HTTPS；如果使用公司、酒店、公共 Wi-Fi，不建议直接暴露。
- 不要把 `8000` 端口做公网端口映射，除非你清楚认证、HTTPS、防火墙和备份策略。
- `data/` 是运行数据目录，应定期备份；不要提交到 Git。

## 二、云端部署，通过链接访问

云端推荐结构：

```text
用户浏览器
  -> https://你的域名
  -> Caddy/Nginx 反向代理 80/443
  -> PanWatch 容器 127.0.0.1:8000
```

不推荐直接裸露 `http://服务器IP:8000` 给公网长期使用。公网部署应使用域名、HTTPS、强密码，并限制服务器安全组端口。

### 1. 准备云服务器

最低建议：

- 2 核 CPU、4 GB 内存起步。
- Ubuntu 22.04/24.04 或 Debian 12。
- 安装 Docker。
- 云厂商安全组放行 `80`、`443`；如果临时直连测试，再放行 `8000`。

安装 Docker 示例：

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
```

重新登录服务器后确认：

```bash
docker version
```

### 2. 部署 PanWatch 容器

在服务器拉取或克隆你的仓库：

```bash
git clone https://github.com/LiuzRush/PanWatch.git
cd PanWatch
```

构建镜像：

```bash
docker build -t panwatch:local .
```

启动应用。云端建议只绑定到本机 `127.0.0.1:8000`，由反向代理对外提供 HTTPS：

```bash
docker run -d \
  --name panwatch \
  --restart unless-stopped \
  -p 127.0.0.1:8000:8000 \
  -v panwatch_data:/app/data \
  -e TZ=Asia/Shanghai \
  -e AUTH_USERNAME=你的用户名 \
  -e AUTH_PASSWORD=你的强密码 \
  -e JWT_SECRET=替换成一段随机长字符串 \
  panwatch:local
```

验证服务：

```bash
curl http://127.0.0.1:8000/api/version
```

### 3. 配置域名

在域名 DNS 控制台添加记录：

```text
类型：A
主机记录：panwatch
记录值：你的云服务器公网 IP
```

最终访问地址类似：

```text
https://panwatch.example.com
```

等待 DNS 生效后再配置 HTTPS。

### 4. 使用 Caddy 反向代理，推荐

Caddy 会自动申请和续期 HTTPS 证书。

安装 Caddy：

```bash
sudo apt update
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install -y caddy
```

编辑 Caddy 配置：

```bash
sudo nano /etc/caddy/Caddyfile
```

写入：

```caddyfile
panwatch.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

替换 `panwatch.example.com` 为你的真实域名，然后重载：

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

浏览器访问：

```text
https://panwatch.example.com
```

### 5. 不使用域名时的临时访问

如果只是临时测试，可以直接暴露 `8000`：

```bash
docker run -d \
  --name panwatch \
  --restart unless-stopped \
  -p 8000:8000 \
  -v panwatch_data:/app/data \
  -e TZ=Asia/Shanghai \
  -e AUTH_USERNAME=你的用户名 \
  -e AUTH_PASSWORD=你的强密码 \
  -e JWT_SECRET=替换成一段随机长字符串 \
  panwatch:local
```

然后访问：

```text
http://服务器公网IP:8000
```

这种方式没有 HTTPS，不建议长期使用，也不建议提供给其他人使用。

### 6. 云端运维常用命令

查看容器：

```bash
docker ps
```

查看日志：

```bash
docker logs -f panwatch
```

重启：

```bash
docker restart panwatch
```

升级代码并重建：

```bash
git pull
docker build -t panwatch:local .
docker stop panwatch
docker rm panwatch
docker run -d \
  --name panwatch \
  --restart unless-stopped \
  -p 127.0.0.1:8000:8000 \
  -v panwatch_data:/app/data \
  -e TZ=Asia/Shanghai \
  -e AUTH_USERNAME=你的用户名 \
  -e AUTH_PASSWORD=你的强密码 \
  -e JWT_SECRET=替换成一段随机长字符串 \
  panwatch:local
```

备份数据卷：

```bash
docker run --rm \
  -v panwatch_data:/data \
  -v "$PWD":/backup \
  alpine \
  tar czf /backup/panwatch_data_backup.tgz -C /data .
```

### 7. 云端安全建议

- 必须设置强 `AUTH_PASSWORD` 和随机 `JWT_SECRET`。
- 优先使用 HTTPS 域名访问，不要长期使用公网 `:8000`。
- 云服务器安全组只放行 `22`、`80`、`443`；应用端口 `8000` 只绑定 `127.0.0.1`。
- SSH 建议使用密钥登录，关闭密码登录。
- 定期备份 `panwatch_data` 数据卷。
- 不要把 `.env`、数据库、API Key 或 `data/` 目录提交到 Git。
